## 1. Тема, номер і варіант

* **Тема:** Python-пакет, що читає CSV, перетворює поля на типізовані значення, будує звіт за списками, словниками й множинами та записує його в текстовий файл.
* **Предметна область:** «Готель».
* **Номер варіанта:** 14.
* **Вимоги варіанта:** поля `room,guest,check_in,check_out,rate`; відбір — активне бронювання на `reference_date`; словник — кількість за `rate`; множина — гості; звіт — завантаження номерів і найдовше проживання.
* **reference_date:** `2026-01-03` (формат ISO `YYYY-MM-DD`), змінюється параметром `--reference-date`.
* **Операційна система:** Windows 11 (PowerShell); CI додатково перевіряє Ubuntu та macOS.
* **Версія Python:** 3.14.5 (локально); мінімальна за `pyproject.toml` — 3.11; у CI — 3.12.

## 2. Мета роботи

Створено Python-пакет `kzp_lab06` із модулями завантаження, аналізу, формування звіту й командного рядка. Програма читає CSV через `csv.DictReader` з явним UTF-8, перетворює рядкові поля на `int`, `float` і `date`, виконує відбір, агрегування та пошук унікальних значень і записує детермінований текстовий звіт. Помилки даних повідомляються винятком `DataError` з номером рядка та назвою поля. Поведінку перевірено `pytest`, якість коду — `ruff`, пакет збирається у wheel.

## 3. Формат CSV

**Заголовок:** `room,guest,check_in,check_out,rate` (порядок стовпців довільний, назви обов'язкові).

| Поле | У файлі | Після перетворення | Правило |
| :--- | :--- | :--- | :------ |
| `room` | текст | `int` | більше нуля |
| `guest` | текст | `str` | не порожнє; зайві пробіли прибираються |
| `check_in` | текст | `datetime.date` | ISO `YYYY-MM-DD` |
| `check_out` | текст | `datetime.date` | ISO `YYYY-MM-DD`, пізніше за `check_in` |
| `rate` | текст | `float` | скінченне й не від'ємне; нуль дозволено |

**Вхідний файл `data/input.csv`:**

```text
room,guest,check_in,check_out,rate
101,"Doe, John",2026-01-01,2026-01-04,150.00
101,Anna Bell,2026-01-04,2026-01-06,150.00
205,Diana Prince,2026-01-03,2026-01-10,220.50
210,Sarah Connor,2026-01-01,2026-01-11,200.00
301,Dexter Morgan,2025-12-27,2026-01-03,1000.00
404,"Doe, John",2026-01-02,2026-01-07,2000.00
102,Clark Kent,2026-01-05,2026-01-06,0.00
```

Набір відповідає вимогам до даних варіанта:

* **сім записів** (потрібно щонайменше шість);
* **текстове поле з комою:** `"Doe, John"` записано в лапках (екранований рядок);
* **дубльоване значення для множини:** гість `Doe, John` має два бронювання, номер 101 трапляється двічі;
* **граничні записи відбору:** номер 205 заїжджає саме 2026-01-03 (активний), номер 301 виїжджає саме 2026-01-03 (уже не активний), номер 101 має останню ніч 2026-01-03 (активний);
* **граничний числовий запис:** тариф `0.00`;
* **порожній результат відбору:** для дати `2026-02-01` активних бронювань немає (перевірено тестом і запуском CLI).

**Правило порожнього входу.** Файл лише із заголовком (`data/empty.csv`) є коректним: список записів порожній, звіт містить нулі, код завершення 0. Файл без заголовка (0 байтів) відхиляється з `DataError`, бо його неможливо відрізнити від пошкодженого.

## 5. Перетворення даних

Запис — словник `dict[str, Any]` із ключами `room`, `guest`, `check_in`, `check_out`, `rate` та похідними `nights` і `cost`. Перетворюються п'ять полів: `room` → `int`, `guest` → нормалізований текст, `check_in` і `check_out` → `date`, `rate` → `float`.

* **Список** зберігає записи в порядку файла (`load_records` повертає `list`), а також результат відбору.
* **Словник** зіставляє тариф із кількістю бронювань.
* **Множина** зберігає гостей і номери без повторів.

Comprehensions:

```python
# list comprehension: відбір активних бронювань
selected = [record for record in records if is_active(record, reference_date)]

# set comprehension: гості без повторів
return {record["guest"] for record in records}

# dict comprehension: ключі словника за зростанням тарифу
return {rate: counts[rate] for rate in sorted(counts)}
```

Підрахунок за тарифом виконано звичайним циклом із накопиченням у словнику: він проходить записи один раз, тоді як comprehension із вкладеним підрахунком проходив би їх для кожного тарифу.

## 6. Функції

```python
def make_summary(
    records: list[Record],
    *metrics: str,
    minimum_nights: int = 1,
    **labels: str,
) -> dict[str, Any]:
```

* **`*metrics`** — довільна кількість назв числових полів (`cost`, `nights`, `rate`); усередині функції це кортеж.
* **`minimum_nights=1`** — типове значення; відбираються проживання не коротші за мінімум. Значення незмінюване, тому не створює стану між викликами.
* **`**labels`** — словник підписів для метрик.

```python
make_summary(records, "nights", "cost", nights="Ночей", cost="Вартість")
# {'count': 7, 'Ночей': 35.0, 'Вартість': 21293.5}

make_summary(records, "nights", minimum_nights=7)
# {'count': 3, 'nights': 24.0}
```

Невідома метрика (`make_summary(records, "guest")`) і підпис для невибраної метрики спричиняють `ValueError`. Якщо всі записи відсіяно, відома метрика дорівнює `0.0`: це відрізняє коректний порожній результат від помилки в назві поля.

## 7. Алгоритм аналізу

1. **Відбір.** `active_on(records, reference_date)` залишає бронювання з `check_in <= reference_date < check_out`: день заїзду й остання ніч активні, день виїзду вже ні. Результат упорядковано за номером кімнати й датою заїзду.
2. **Агрегування за ключем.** `count_by_rate(records)` повертає словник «тариф → кількість».
3. **Унікальні значення.** `unique_guests(records)` повертає множину гостей.
4. **Завантаження номерів.** `occupancy(records, reference_date)`: множина номерів з активним бронюванням, поділена на множину всіх номерів файла. Два бронювання одного номера рахуються як один номер.
5. **Найдовше проживання.** `longest_stay(records)`: найбільша кількість ночей; за рівності менший номер кімнати, далі раніший заїзд. Для порожнього набору `None`.
6. **Підсумок.** `build_report` збирає всі показники в словник без форматування.

**Детермінований порядок.** Активні бронювання впорядковано за номером і заїздом, тарифи за зростанням, гості за алфавітом, числа мають два знаки після крапки. Тест `test_report_does_not_depend_on_input_order` перемішує записи й отримує той самий текст.

## 8. Обробка помилок

`DataError(ValueError)` означає помилку формату або значення вхідних даних. Перетворення виконується на межі входу, і першопричина зберігається через `raise ... from error`:

```python
def _parse_float(row: dict[str, str], field: str, row_number: int) -> float:
    try:
        return float(row[field].strip())
    except (AttributeError, KeyError, TypeError, ValueError) as error:
        raise DataError(f"Рядок {row_number}: поле {field} має бути числом") from error
```

| Ситуація | Повідомлення | Першопричина (`__cause__`) |
| :------ | :------ | :----- |
| файл без заголовка | `Файл порожній: немає рядка заголовка` | — |
| відсутній стовпець | `У заголовку немає стовпців: rate` | — |
| зайвий стовпець | `У заголовку зайві стовпці: note` | — |
| відсутнє значення в рядку | `Рядок 3: немає значення поля check_out` | — |
| зайве значення (кома без лапок) | `Рядок 2: забагато значень` | — |
| хибне число | `Рядок 3: поле rate має бути числом` | `ValueError` |
| хибна дата | `Рядок 2: поле check_in має бути датою у форматі YYYY-MM-DD` | `ValueError` |
| від'ємний тариф | `Рядок 2: поле rate не може бути від'ємним` | — |
| виїзд не пізніше заїзду | `Рядок 2: поле check_out має бути пізніше за check_in` | — |
| файла немає | `Не вдалося прочитати файл: <шлях>` | `OSError` |
| файл не в UTF-8 | `Не вдалося прочитати файл: <шлях>` | `UnicodeDecodeError` |

Голого `except` і `except Exception` у коді немає. Номер рядка береться з `reader.line_num`, тому враховує заголовок і багаторядкові поля.

**Коди завершення CLI:**

| Код | Значення |
| :-- | :------ |
| 0 | звіт записано |
| 2 | помилка вхідних даних; повідомлення `Помилка даних: ...` у stderr, звіт не створюється |
| 3 | звіт не вдалося записати (`OSError`) |

Для stderr явно задається UTF-8, бо консоль Windows може мати інше кодування. Traceback користувачу не показується. Якщо вхідний і вихідний шляхи збігаються, програма завершується з кодом 2 і не змінює вхідний файл.

## 10. Тестування

Усього **69 тестів pytest** (з урахуванням параметризованих випадків).

| Файл | Тестів | Що перевіряє |
| :--- | :-- | :---------- |
| `tests/test_loader.py` | 32 | типи полів, нормалізація, кома й лапки, CRLF, порядок стовпців, порожній вхід, заголовок, рядки, значення, файл |

* **Позитивні:** контрольний файл дає сім записів і звіт, що збігається з `reports/summary.txt`.
* **Порожній вхід:** файл лише із заголовком, файл 0 байтів, порожній список для кожної функції, порожній результат відбору.

* **Граничні:** день заїзду, остання ніч, день виїзду; тариф 0; `minimum_nights` на межі; один запис.
* **Негативні:** хибне число, хибна дата, відсутній стовпець, зайвий стовпець, відсутнє значення в рядку, зайве значення, від'ємний тариф, `nan` і `inf`, незакриті лапки, відсутній файл, файл не в UTF-8; перевіряється `__cause__`.
* **Запис звіту:** створення каталогів, UTF-8, LF, перезапис довшого файла.
* **CLI:** успішний і помилковий сценарії, зокрема через окремий процес `python -m kzp_lab06.cli`.

Тести перевіряють зовнішню поведінку (значення, тексти, коди завершення), а не внутрішні змінні. Тимчасові файли створюються через `tmp_path`.

## 15. Відповіді на контрольні питання

1. **Яку роль виконує pyproject.toml у Python-проєкті?** Це єдиний опис проєкту: назва, версія, мінімальна версія Python, залежності, команда запуску та налаштування інструментів (pytest, ruff).
2. **Навіщо створюється віртуальне середовище?** Воно ізолює залежності проєкту від системного Python та інших проєктів і відтворюється за `pyproject.toml`.
3. **Чому CSV-файл відкривається з newline=""?** Щоб модуль `csv` сам обробляв роздільники рядків; інакше перенесення рядка всередині поля в лапках або `\r\n` можуть зіпсуватися.
4. **Які типи повертає csv.DictReader без додаткового перетворення?** Словники, де всі значення є рядками (`str`); числа й дати треба перетворювати окремо.
5. **Чому split(",") не є коректним CSV-парсером?** Він ділить і по комі всередині лапок, тому `"Doe, John"` стане двома полями, і не розуміє подвоєних лапок.
6. **Як відрізняються список, словник і множина?** Список зберігає порядок і повтори, словник зіставляє ключ зі значенням, множина зберігає лише унікальні значення без гарантії порядку.
7. **Коли comprehension робить код зрозумілішим, а коли краще використати цикл?** Він добрий для одного простого відбору або перетворення. Для вкладених умов, побічних ефектів чи накопичення зрозуміліший звичайний цикл.
8. **Що містять *args і **kwargs усередині функції?** `*args` — кортеж зайвих позиційних аргументів, `**kwargs` — словник зайвих іменованих аргументів.
9. **Чому змінний об'єкт небезпечний як значення за замовчуванням?** Він створюється один раз під час оголошення функції, тому зміни зберігаються між викликами.
10. **Як raise ... from error зберігає першопричину?** Початковий виняток записується в атрибут `__cause__` нового, і traceback показує обидва.
11. **Чому завантаження, аналіз і запис звіту розділяються на модулі?** Кожну частину можна тестувати й змінювати окремо: аналіз перевіряється без файлів, а формат звіту змінюється без впливу на читання.
12. **Яку гарантію дає with під час роботи з файлом?** Файл буде закрито після виходу з блоку, навіть якщо всередині виник виняток.
13. **Чому звіт має формуватися в детермінованому порядку?** Щоб однакові дані завжди давали однаковий текст: інакше тести й порівняння звітів були б нестабільними.
14. **Які випадки повинні бути перевірені для порожнього CSV?** Файл лише із заголовком, файл без жодного рядка, порожній результат кожної функції аналізу й текст порожнього звіту.
15. **Чим тест поведінки відрізняється від перевірки внутрішньої реалізації?** Тест поведінки перевіряє результат функції для заданого входу й не ламається, коли внутрішній код переписано без зміни результату.
16. **Які файли знаходить pytest?** Файли `test_*.py` або `*_test.py`, а в них функції `test_*` і методи класів `Test*`.
17. **Які перевірки виконує ruff?** `ruff check` шукає помилки й порушення стилю (невикористані імпорти, застарілі конструкції), `ruff format --check` перевіряє форматування без зміни файлів.
18. **Які коди завершення має CLI для успіху та очікуваної помилки?** 0 для успіху, 2 для помилки вхідних даних; у цій роботі ще 3, якщо звіт не вдалося записати.
19. **Чому в CI запускаються і тести, і аналізатор, і пакетування?** Вони перевіряють різне: тести — поведінку, аналізатор — якість коду, пакетування — що пакет справді встановлюється й запускається.
20. **Які дані та результати потрібно задекларувати в REPORT?** Формат CSV і приклад входу, значення `reference_date`, повний текст звіту, повідомлення про помилки й коди завершення, команди та результати pytest, ruff, wheel і CI.
